Abstract

Question: How do we turn many fragmented SAM texture proposals into one coherent binary mask, without cheating on RWTD test labels?

Incentive: RWTD is binary-mask evaluation, and ARI strongly penalizes fragmentation. Coverage alone is not enough.

Intuition: keep high-recall proposals from SAM, then learn which fragments belong together from a large external texture dataset (PTD), not from RWTD labels.

Main thread: diagnose fragmentation, build PTD-only consolidation models, freeze everything, run RWTD once.

Leakage-Safe Protocol

Leakage statement: RWTD labels are used only for the final metric computation step. They are not used to train weights and not used for parameter search.
  • External training data: PTD only (246,285 images, 56 texture classes).
  • RWTD role: final test set only.
  • Frozen pipeline: configuration and learned models fixed before final RWTD scoring.

Step-by-Step Pipeline (Easy Words)

  1. SAM generates many candidate masks per image (high recall, deliberately over-complete).
  2. For each mask, we compute texture embeddings (handcrafted or PTD-trained encoder features).
  3. We build a mask-neighborhood graph and merge pieces that look texture-consistent and spatially connected.
  4. From merged components, PTD-v7 uses a dual-AI decision gate: v4 primary prediction plus v6 rescue on low-coverage evidence.
  5. In strict PTD-v7 mode, merge remains PTD-v3 learned while foreground decision uses v4+v6 AI gating.

How We Generate Many Candidate Masks

  • Source: official TextureSAM η≤0.3 automatic masks at reports/repro_upstream_eval/official_0p3_masks.
  • Average candidate count used by consolidation: 3.84375 masks/image (from strict summary).
  • Why so many: the method favors recall first, then solves coherence by consolidation.

What Are v2/v3/v4/v5 Prompts, and Why Those Texts?

What they are: versioned prompt templates for upstream SAM/VLM proposal generation runs.

How they differ: different wording, scan strategy, and attribute phrasing produce complementary proposal sets.

Why those texts: they intentionally diversify candidate masks so true regions are less likely to be missed.

Why this is valid: strict PTD-v7 does not train on RWTD labels; proposal diversity and dual-gate logic are fixed pre-test.

Why This Is Not Benchmark Manipulation

  • No RWTD-label training.
  • No RWTD-label hyperparameter tuning.
  • External learning comes from PTD and PTD-derived synthetic masks.
  • Method is designed around a general texture-coherence principle, then tested on RWTD once.
